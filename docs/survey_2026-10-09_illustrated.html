1このコンペは何をするのか

太陽を H-Alpha(太陽観測で使う赤い光)で撮った 2048×2048 の画像が、学習用に 707 枚・ テスト用に 180 枚ある。やることは「どこかにフィラメントがある」を見つけることではなく、 インスタンスセグメンテーション (1本1本を区別して、形そのものを塗り絵のように切り抜くこと)。 全部まとめて「フィラメントっぽい領域」を出す方式は過去に試して惨敗済み(Public 0.19)で、 「個体単位で出す」のがこのコンペの勝負どころ。

出すのは「フィラメント1本ごとの塗り絵」。本数も形も両方正解しないと点が来ない。

2点数の付け方(PQ)

PQ = Σ IoU(当たったペア) ÷ ( 当たり数 + 0.5 × 空振り数 + 0.5 × 見逃し数 )
分子 = 当たったものの形の正確さの合計。分母 = 当たり + 外れの半分 + 見逃しの半分。

このコンペの点数は PQ(パノプティック品質:当てた個数と形の正確さを まとめた点数)。いちばん大事な仕様は IoU(重なり具合)が 0.5 を超えないと「当たり」に ならないこと。しかも外すと、出した予測は「空振り(FP)」・残った正解は「見逃し(FN)」として 分母を両方から膨らませるので、惜しい予測ほど損。さらに正解は人(アノテータ)ごとに 複数版あり、同じ提出がそれぞれと別々に採点されて合算される。

「出せば当たるかも」ではなく「出して外すと減る」— 出す/出さないの判断自体が得点源。

4ルールで許されること / ダメなこと

新しく出た裁定で線引きがはっきりした。外部の正解データ(人手で塗ったフィラメント集)は禁止、 推論時に時間前後の画像を参照するのも禁止。いっぽう訓練フェーズ限定なら、 正解のない追加の太陽写真(GONG アーカイブ)や、同時刻の磁場図を副タスクに使うこと、 白黒画像を3枚重ねにする前処理は、全部OKと明言された。

私たちの今のやり方は全部セーフ。外部データ系の権利は「訓練限定」という条件付きで残っている。

5私たちのパイプライン(現状)

流れはシンプル。YOLO11m(物体検出AI)が「フィラメントっぽい塊」を見つけ、 U-Net refiner(形を整える小さいAI)が各候補をキレイにする。refiner は shrink(削るだけ・伸ばせない)が一番良かった — つまり YOLO の候補は 最初から大きめに覆っている。最後に、同じ画像内でマスクが1画素も重ならないよう 排他化して提出する。 OOF(学習に使っていないデータでの手元採点)は 0.4432。

「候補を見つける→形を整える→重なり消し」の3段。弱点は conf 0.26 という手動の足切り。

6最前線: tushhaaarrrr 氏の設計

彼の設計の核心は、モデルを巨大化することではなく「どの候補を提出に入れるか」の決定層。 まず「ランダムなアノテータがその画素を塗る確率」を素直に学習させ (ごまかしの効く損失は全部不採用)、15段階の閾値でできる入れ子ツリー上の全候補に、 期待IoU û(「当たる確率」×「当たった時の形の良さ」の掛け算)を 勾配ブースティング(弱い木をたくさん足す機械学習)で予測。 最後に「û が τ を超える候補だけ」を木の最適化で選ぶ。

スコア差の源泉はモデルではなく決定層。「候補に値段を付けて、損しないものだけ出す」が勝ち筋。

7なぜ「どれを出すか」の判断が点数を決めるのか

§2 で見た通り、外れた候補は「0点」ではなく分母を増やす罰金。だから候補を1つ出す行為には 「当たったら IoU 分だけ得」「外れたら 0.5×PQ だけ損」という期待値の天秤がある。 README §1 に最初から書かれている損益分岐 p·u > 0.5·PQ と、 tushhaaarrrr 氏の「û > τ(τ=PQ/2≈0.26)で選択」は同じことを言っている。 違いは、彼がこの計算を全候補に機械学習で回しているのに対し、私たちは conf 0.26 の 固定足切りで済ませていること。

「全部出す」は愚策。「損しないものだけ出す」を自動化した側が勝つ — それが τ=PQ/2 の意味。

8私たちとの違い(対応表)

一番大きい差は①。こちらは「YOLO の自信 0.26 以上」を全画像共通の関所にしているが、 向こうは候補ごとに「これを出したら期待してよい点数(û)」を推定して、PQから決まる 一つの関所 τ で選ぶ。③の回転正規化クロップは、細長いフィラメントを 「いつも横向き」に揃えてから整える工夫。

なお過去の失敗との違い: 私たちは V42 で候補採点器(verifier)を一度作って 不採用にしたことがあるが、あれは refiner 前の代理目標を当てにしていたので 最終PQに結びつかなかった。今回の案は refiner 後の「最終的に当たる度合い (期待IoU)」を直接予測する点が違う — まさに失敗の原因を取り除いた形。

「候補採点器」は二度目の挑戦だが、今回は失敗した V42 と違い「最終形の良さ」を直接狙う設計。

9Biohub(細胞追跡)から借りられるもの

Biohub(細胞追跡コンペ、2026-09 終了)の1位は、巨大モデルではなく 小さいモデルを段々に並べる設計だった: 検出は 3.1M の U-Net (事前学習→手描き1,800細胞で微調整→自分で作った擬似正解で再学習)、 "Soon Net" は各細胞の3フレームから「分裂しそうか」を分類する軽量CNN+Transformer (2周目は OOF で誤分類した難しい例 2,492 件を 1:1 で混ぜて再学習)、 連結は Transformer + 欲張り法。3位は検出ヒートマップを複数モデルで確率平均し、 不確かな背景(候補周囲6µm)を損失から除外。12位は再学習せず「計測済みの修復段」を積んで Private でほぼ持ちこたえた(ただし検証が in-sample で約0.03 楽観だったと自己申告)。

10これからの優先順位

優先度1は「期待IoUスコアラー + τ選択」で、YOLO の足切りを緩めて(conf 0.10程度)候補を増やし、 refiner 後の候補ごとに「出したら期待できる点数」を学習予測して τ で選ぶ。 既存の OOF キャッシュに候補が残っているのでGPU不要・CPUだけで検証できるのが大きい。 過去の失敗(V42)と違い、目標は「最終的に当たる度合い」そのもの。2番目の確率平均は推論だけで済む 安い改善候補。3番目は再学習が要るので後回し、4番目は締切(11/15)に向けた提出物の整備。

まずやるのは「スコアラー」— GPU不要・既存データで試せて、tushhaaarrrr 氏の +0.06 の源泉と同じ原理(私たちの構成でどれだけ効くかは未測定)。

11「惜しい」はなぜ損なのか — 手計算で体感する PQ

分子に入るのは「当たったペアの IoU の合計」だけ。だから IoU 0.4 の惜しい候補を足しても 分子は1円も増えず、分母だけ「空振り+0.5・見逃し+0.5」で膨らむ(ケースB)。 同じ候補でも形を 0.55 まで良くすれば当たりに昇格して分子+分母の両方に効く(ケースC)。 私たちのデータでは「惜しい」候補(near-miss、IoU 0.3〜0.5)が 920 件残っていて、 これが全部当たりに変われば PQ は約 0.50 まで届く計算 — README §2 の見通しそのもの。

出すか出さないかの前に「形を0.5の崖の上に乗せられるか」が勝負。惜しいまま出すのは最悪手。

12人間同士でも 0.34 — 「正解」がぶれる問題

衝撃の事実: アノテータ A さんの描画を B さんの正解として採点すると、PQ は 0.3398(複数アノテータ観測296枚。tushhaaarrrr 氏も別の598ペアで 0.340 と同じ値)。 細いリボンは数ピクセルの輪郭のずれで IoU が大きく削られるから、人間同士でもこの点数にしか ならない。逆に言えば、複数人の正解の「平均」を学んだ機械は、個々の人間より高く出せる — だから tushhaaarrrr 氏の「アノテータが塗る確率をそのまま学ぶ (soft annotator-mean)」という目標は理にかなっている。

正解がぶれるコンペでは「誰か一人の描き方」を真似るより「みんなの真ん中」を学ぶ方が得。0.44 は人間並みを既に超えている。

13検出器の足切りを下げると何が起きるか — 実測

現行の足切り conf 0.26 より下にも、本物の候補はまだ残っている(TP 5017@0.20 → 5420@0.08)。 ところが足切りを下げると、空振り(FP)がそれ以上に爆発する — 0.08 では FP 6370 件。 juanmirod 氏の別視点の計測でも同じ構図: 足切りを緩めれば正解の9割に候補は届くのに、 混ざる大量のゴミを見分ける仕組みがない。 つまり「候補はもうある。選別器がない」— これがスコアラー案の前提。

「もっと候補を出せば当たりも増えるがゴミも増える」→ だから候補ごとの良し悪しを見る仕組みが要る。

16検証の作法 — 3-fold OOF と「fold0 だけで喜ばない」

fold(フォールド)は学習データの三等分。各 fold の採点には 「そのfoldを見ていないモデル」を使うから、ズルをしない前哨戦の点数(OOF)になる。 でも罠がある: fold0 だけで最良を探すと「fold0 専用の設定」を拾ってしまう。 実際に free variant の閾値 0.86 は fold0 では −0.003 だったのに、fold1/2 では −0.016/−0.011 と一致して悪かった。このプロジェクトでは「3fold で改善の符号が一致 + bootstrap の95%信頼区間が0を跨がない」ことだけを採用条件にしている。

「一番良かった場所」ではなく「全部の場所で良いか」で決める。これが過去の失敗から生まれた採用ゲート。

TTAテスト時拡張。画像を反転・回転した複数版で予測して平均する技。確率平均はOK、形の多数決は要注意。
EMA学習中の重みの「なめらかな平均」を別に持ち、そちらで推論する技術。微小な改善が見えている。
pseudo-label自分のモデルが生成した「仮の正解」で追加学習する手法。ここでは2fold一致で悪化し不採用。
shrink refinerYOLO候補の「内側だけを削って」形を整えるU-Net。伸ばせないのがポイント。

18FAQ

0.55 のチームに勝てないの?

作者の調査では公開データとの重複を指摘する参加者発言や、運営の精査方針が記録されています。ただし個別提出の使用データや違反の裁定は今回確認していません。0.40前後は作者が参照した公開報告の帯域で、0.39との独立・同条件の性能比較ではありません。

なぜモデルを大きくしないの?

試した結果が全部あるから(yolo11l・RF-DETR置換・多チャンネル化など§15参照)。学習データ707枚では、モデル容量より「どれを出すか」の決定層の方が差を生むと3者の実測が一致して示している。

外部データを使えば?

正解付きの外部データはルールで禁止。ラベルなし太陽写真は訓練に使えるが、pseudo-labeling(V49)は2fold一致で悪化確定済み。MAE事前学習は権利として残っているが効果不明で優先度は低い。

Public 0.39 と 0.40 は違うの?

表示上の差はほぼ誤差。採点は約90枚だけで、リサンプリング誤差だけで sd≈0.012 ある。本質的な差は OOF にある(私たち 0.4432 vs tushhaaarrrr 氏 0.4597)ので、そこを詰めるのが今の計画。

締切(2026-11-15)までに何を出す?

定量70%は提出CSV。それに加えて定性30%として「4ページ技術報告書 + 公開Gitリポジトリ(+再現notebook)」を Google Form で提出しないと最終評価の対象外。コードの見た目・文書化も採点対象。
